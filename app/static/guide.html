车辆控制 · 帮助

工作原理

新固件特斯拉只接受端到端签名的控制指令(Vehicle Command Protocol),面板本身不保存 Tesla 凭证,而是把指令转发给你配置的「指令后端」——由它签名并下发:

TESLA Home 面板→ 指令后端(签名)→ Tesla 云端→ 你的车

指令后端两种选择:托管服务(注册即用,推荐)或自建官方代理(完全自主,免费额度内 $0)。 两种都只需在 .env 填两个值:CONTROL_API_URL 和 CONTROL_API_TOKEN。

方案一:托管服务 推荐 · 约 10 分钟

MyTeslaMate(按量计费,无月租)或 Teslemetry(包月)会代管密钥与签名,省去全部基础设施。

  1. 注册托管服务

    打开 myteslamate.com 或 teslemetry.com 注册账号, 按他们的指引创建 Tesla 开发者应用(公钥由他们托管)。

  2. Tesla 账号授权

    用 Tesla 账号在托管服务页面登录授权,授权范围勾选车辆数据与车辆控制 (vehicle_cmds / vehicle_charging_cmds)。

  3. 配对虚拟钥匙(Virtual Key)

    在手机上打开托管服务提供的配对链接 / 二维码,会跳转 Tesla App 确认配对;车内屏幕无需操作。这一步把「允许该应用控制车辆」写进你的车。

  4. 拿到 API Token 填入 .env

    在服务器编辑 ~/teslamate-visualizer/.env: 
    CONTROL_API_URL=https://api.teslemetry.com   # 以服务商页面为准
CONTROL_API_TOKEN=粘贴你的 Token
CONTROL_VIN=          # 留空 = 自动取数据库第一辆车

  5. 重启面板

    cd ~/teslamate-visualizer && docker compose up -d (环境变量改动无需重新构建)。回到面板「控制」页,点「闪灯」实测。

方案二:自建官方代理(全自主)

使用特斯拉官方开源的 tesla-http-proxy (github.com/teslamotors/vehicle-command), 适合想完全掌控密钥的场景。需要你有一个域名(本面板的域名即可)。

  1. 注册 Tesla 开发者应用

    打开 developer.tesla.com → Dashboard → 创建应用:填应用名、域名(如 www.friday-keeper.icu)、回调 URL; 中国区车辆区域选 China。创建后得到 Client ID / Client Secret。

  2. 生成密钥对(虚拟钥匙的"钥匙")

    在服务器执行: 
    openssl ecparam -name prime256v1 -genkey -noout -out private-key.pem
openssl ec -in private-key.pem -pubout -out public-key.pem
    private-key.pem 是签名私钥,绝不外传,只交给本机的 tesla-http-proxy 容器。

  3. 托管公钥(本面板已内置)

    Tesla 要求从你的域名拉取公钥验证身份。把 public-key.pem 复制为 ~/teslamate-visualizer/data/tesla-public-key.pem,面板会自动在 https://<你的域名>/.well-known/appspecific/com.tesla.3p.public-key.pem 提供(公开路径,无需登录)。浏览器访问该地址确认能下载再继续。

  4. 注册 partner account

    用 Client ID 换 partner token 后,向 Fleet API 注册域名(以官方文档 fleet-api 的 POST /api/1/partner_accounts 为准,中国区用 fleet-api.prd.cn.vn.cloud.tesla.cn)。

  5. 运行 tesla-http-proxy

    Docker 启动官方代理,挂载 private-key.pem,加入面板所在 docker 网络; 代理会对外暴露与 Fleet API 同形态的 /api/1/vehicles/<vin>/command/<cmd> 端点。

  6. OAuth 拿用户令牌

    按官方认证流程(authorization code flow)用 Tesla 账号授权,scope 至少包含 openid offline_access vehicle_device_data vehicle_cmds vehicle_charging_cmds, 得到 access token(过期用 refresh token 续期)。

  7. 配对虚拟钥匙

    用 vehicle-command 工具生成配对链接 / 二维码,手机 Tesla App 打开确认。

  8. 配置 .env 并重启

    CONTROL_API_URL=http://<proxy容器名>:8080
CONTROL_API_TOKEN=<上一步的 access token>
    docker compose up -d 后到「控制」页实测。

使用与安全须知

  • 休眠唤醒:车辆休眠时首条指令会先唤醒(10–30 秒)。唤醒(wake_up)是计费里最贵的操作($0.02/次),面板不会自动轮询唤醒。
  • 费用:Fleet API 按量计费,控制指令 $0.001/次;每个开发者账号每月 $10 免费额度,个人使用基本免费。
  • 权限即控制权:能登录面板账号的人就能控制车辆(解锁/开箱需二次确认,但仍属敏感)。面板账号务必使用强密码。
  • 故障排查:控制页提示「指令后端未配置」→ 检查 .env 两项是否填好并已 docker compose up -d;提示 502 → 检查代理容器与令牌有效期。
⚠️ 面板未提供「远程启动驾驶」入口——该指令可让无钥匙开走车辆,风险过高;如确有需要请自行通过代理调用。
