# 车辆控制与午休

控制配置入口位于个人中心，仅管理员可见。首次未配置时，控制页显示前往个人中心的入口。配置页复用现有加密存储及一次性 OAuth 会话绑定，不向浏览器返回客户端密钥、访问令牌、刷新令牌或签名私钥。

控制页沿用原有车辆模型，标注设定温度、车内温度、车锁、哨兵、车窗、前后备箱、充电口状态。模型部位与下方空调、充电、车灯、午休模块打开独立操作弹窗。只读账号可查看，无法发送操作。

状态通过「刷新车辆状态」主动查询 Fleet vehicle_data，只提取必要字段，不持久化原始响应和位置。相邻请求最少间隔十秒；同一页面定期查询的是面板缓存，不会持续轮询 Tesla。数据超过两分钟显示未知，TeslaMate 仅补充近期明确上报的字段，不将最后指令作为当前状态。

午休设置为立即开始，持续 5–180 分钟。服务器先持久化关闭任务，再发送 climate_keeper_mode=3，到期发送 climate_keeper_mode=0。重启不会再次发送开启指令，已过期任务会继续关闭。网络异常或关闭未确认时持久化重试，界面显示待确认，需在 Tesla App 检查；无法保证服务器或车辆断网时按秒关闭。结束只退出露营模式，不额外发送关闭空调指令。

开始前要求车辆上报气候保持模式为 off，避免覆盖已有宠物/驻车空调/露营模式。结束前再读取状态，如用户已切换到其他模式，不发送关闭指令。任务保存原 VIN，整个任务期间禁止替换客户端凭据或重新授权；完成后解除限制。程序采用现有单 worker 部署。

`data/control-nap.json` 为任务持久化文件，权限 0600，不包含 OAuth 密钥，包含任务车辆标识。与其他私有 data 文件一样不要提交 Git。迁移或停机维护前应先在页面结束午休并确认，迁移时保留该文件以及原 Fleet 凭据、签名私钥和解密密钥。主机彻底下线期间不能执行定时任务。

测试使用模拟车辆，覆盖到期关闭、重启恢复、重复任务、网络失败重试、开启超时后的清理、用户改用宠物模式与权限隔离。部署不自动测试真实车辆指令。

参考：[Tesla 控制指令](https://developer.tesla.com/docs/fleet-api/endpoints/vehicle-commands)、[车辆数据接口](https://developer.tesla.com/docs/fleet-api/endpoints/vehicle-endpoints)。
